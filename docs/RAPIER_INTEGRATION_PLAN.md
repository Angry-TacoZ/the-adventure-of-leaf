# Rapier integration plan for PR #4

The current deterministic clock owns one FIXED_STEP=1/120-second update. Rapier must replace the relevant step implementation, not add a second clock. Input sampling, restart and lap reset must be forwarded to that owner. No Rapier runtime is installed in PR #3.

`physics-boundary.ts` supplies renderer-independent water height, slope and unit normal, current, wind, time and obstacle descriptors by adapting the current simulation functions. Future particle buoyancy samples these values at particle world positions. Drag/current and wind forces must be timestep-scaled; calibrate buoyancy against displaced area/mass. Rock circles currently describe horizontal constraints; PR #4 must choose explicit rigid collider shapes without changing obstacle placement.

The presentation boundary defines pose plus stable fragment IDs, vertex positions, normals, UVs and optional index buffers. PR #4 must implement the buffer consumer: retain buffers when topology is unchanged, update attributes/normals for deformation, and replace/dispose geometry only after topology changes. Particle-to-vertex mappings and UV seams require explicit ownership. Multiple connected pieces require separate fragment meshes; do not assume a single rigid pose describes every torn piece. The current renderer consumes the rigid pose, while deformable fragment upload is still future work.

Official JavaScript references: [soft bodies](https://rapier.rs/docs/user_guides/javascript/soft_bodies/) and [tearing](https://rapier.rs/docs/user_guides/javascript/soft_body_tearing/). These describe particles, constraints, deformable colliders and topology changes. Verify the chosen npm package version actually exposes the documented APIs before installing. Do not assume ordinary rigid-body APIs implement soft-body tearing. Tear events and topology versions must update presentation mappings after the physics step; newly disconnected pieces need their own state.

Keep simulation reproducible at fixed steps, with tests for force units, resets, collider passage and topology ownership. WASM initialization, memory growth and crossing the JS/WASM boundary per particle can dominate cost; batch reads/updates and measure on target browsers. Do not transfer render buffers while Three.js still owns them. Hardware rendering performance and soft-body solver iteration budgets need measurement before selecting particle density.

Interface review follow-up (2026-10-31): each `LeafMeshData` can now carry its own world pose, with an optional quaternion for physics-driven orientation, a topology revision and stable vertex IDs. Detached pieces cannot share a single rigid pose. Positions/normals remain piece-local; vertexIds map vertices back to particles and must be refreshed after topology changes. UV seams can map multiple vertices to the same particle. A frame's fragment list is a complete snapshot: absent IDs are removed/disposed by the future consumer. Optional indices mean non-indexed geometry, not 'keep old indices'. The quaternion, when supplied, takes precedence over Euler radians in the future consumer; current gameplay still supplies Euler pose. These are presentation contracts, not an implemented deformable mesh renderer. The official JavaScript user guide inspected for this review identifies version 0.21; verify the installed PR #4 package against that API before using soft-body/tear methods.

## Implemented Rapier milestone

Gameplay now uses river-leaf.ts for a single 120 Hz Rapier world; it calls updateWind for shared input/environment state and does not call the legacy leaf-motion solver. Static bank cuboids and spherical rock colliders are coarse approximations. Effective supported thickness is 0.04 m, total blade mass 0.002 kg. Upward acceleration is 19.62 times immersion fraction, vertical water drag is 6/s, and horizontal drag uses the existing drag parameter times immersion. Upstream wind force is bounded by the available downstream current drag rather than directly changing velocity.

The 51-particle surface uses initial uniform softness 30 Hz / damping ratio 1, particle radius 0.008 m, linear damping 0.02/s. Initial tear settings are strain 0.8, force 0.3 N, load smoothing 0.04 s, one element per step. Edge plastic yield is 0.3, creep 0.2/s and maximum plastic strain 0.2. These are engineering tuning values and need physical-feel acceptance. Concentrated stress triggers real engine tear events. The development cut hook uses World.cutSoftBody and frees its returned event; automatic events are drained and freed by Rapier's event queue.

leaf-topology.ts rebuilds a fragment's UVs, source IDs and engine boundary indices after topology version changes. Copied original particles recover source IDs using rest positions; newly interpolated particles use a sentinel and do not invent vein connections. leaf-view.ts owns copied display buffers and removes absent fragments. Current physics positions use a shared world-origin pose. Arbitrary externally supplied per-fragment quaternion poses are not yet consumed by that renderer.
