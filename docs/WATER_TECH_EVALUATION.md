# Water technology evaluation (2026-10-29)
Choose a small independently written WebGL2-compatible Three.js water surface with analytic waves and a shared CPU height/current sampler for the river prototype. This avoids coupling leaf movement to a separate GPU simulation and works on the standard Three.js WebGL renderer; it is an approximation, not full fluid dynamics. Add real reflections/refraction and localized wakes only after evaluating cost and visual need.

- [Evan Wallace's WebGL Water](https://github.com/evanw/webgl-water) is a bounded pool heightfield with raytraced reflection/refraction, caustics and floating-point texture requirements. The repository has no identified license file via GitHub; do not copy it without verified rights. It does not provide an out-of-box downstream river current.
- [Three.js adaptation](https://github.com/jeantimex/threejs-water) is MIT licensed with original and modified copyright notices. Its current package uses Three.js 0.184 and Vite, but its pool simulation and GPU readback/integration cost require additional work for current-driven leaf motion. No code or assets are copied.
- [SeedOcean](https://github.com/reed-soul/SeedOcean) is MIT licensed, WebGPU-first with WebGL2 fallback, FFT waves, foam and buoyancy. Designed for ocean water, it is substantially larger than needed for a narrow current-driven river; combining it with a second engine is unjustified.
- [After Rain](https://github.com/HiliMor/after-rain) is all rights reserved; no copying permitted. It is a visual benchmark only. [Ripple](https://ripple.carsonye.com/) is a movement benchmark; its source/license has not been established, so do not reuse assets or code.

WebGPU may provide headroom later but support, packaging and fallback testing add risk; WebGL2 is the initial target. This model does not yet implement physically correct refraction, dynamic obstacle wakes or true reflection; performance and device compatibility require measurement. Desktop shells must be tested with their actual graphics backends.
