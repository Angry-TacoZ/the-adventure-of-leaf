# Eanpa-Sky fit for the approved thunderstorm

Evaluated November 4, 2026 at [a197d3dc42577e9b870b471a39d6b1710c5b5633](https://github.com/SkyeShark/Eanpa-Sky/tree/a197d3dc42577e9b870b471a39d6b1710c5b5633). Eanpa integration is now present on the draft branch; Pages remains on the earlier verified route checkpoint. James approved adapting its Earth sky/weather with a lighter Low-quality path on November 4. Production integration is the next milestone; the isolated probe does not establish whole-game compatibility. The current valley remains clear-weather until storm presentation is implemented.

The code is MIT, copyright SkyeShark 2026. It uses Three r186 WebGPU/TSL and offers volumetric clouds, cloud shadows, weather transitions, rain and lightning. Its standalone demo vendors modified Three; the [renderer-patch document](https://github.com/SkyeShark/Eanpa-Sky/blob/a197d3dc42577e9b870b471a39d6b1710c5b5633/vendor/three/EANPA_PATCHES.md) explicitly distinguishes those changes from stock upstream. It is not a ready-to-install npm library. A focused adapter would preserve our physics/water rather than importing its demo/renderer. Some demo audio is CC BY-NC-SA; the code license does not make every asset CC0.

An isolated fixture used our stock Three0.186.1 with five unmodified sky modules, the upstream notice and its authored cirrus field. Initial optional MRT stamps produced blank output and native WGSL `structures must have at least one member`. The upstream-supported EANPA_NO_MRT=true switch fixed that configuration for our forward renderer without patching Three or the source modules. Daytime cumulus/stratus/clear then rendered on native NVIDIA WebGPU and hardware ANGLE WebGL2 without captured errors. ACES tone mapping prevented HDR cloud radiance clipping. This proves the basic sky subset, not the full engine.

Conditions: installed headless Chrome156; native NVIDIA Lovelace/non-fallback, WebGL2 ANGLE RTX4090 D3D11; 640×360. The 44 march/14 light-sample/3-pass analytic probe had caches disabled and did not prepare/apply cloud shadows. First renderAsync wall times were ~274.7ms WebGPU and ~67,975.9ms WebGL2. These include shader preparation, are not steady-state GPU timings/FPS, and do not represent its complete Balanced preset. A reduced 12/3/1 case prepared in ~76.6ms/~2,383.7ms but looked visibly grainier. Later ~1ms CPU submission calls do not establish GPU cost. No SwiftShader attempt was made for this expensive module.

Raw probes remain under ignored output/eanpa-probe, output/eanpa-probe-results*.json and output/eanpa-hardware.json; the detailed local report is output/EANPA_EVALUATION.md. The weather field's upstream README identifies its cirrus texture as procedurally authored, without a third-party source photograph. No demo scenery, moon/starmap or audio was imported.

Before adoption, verify whole-game shader startup, rain/lightning, compute-cache/backend compatibility, cloud shadows on instanced trees and the hero, water reflection/submersion, serialized GPU preparation, quality/resize/disposal and matched steady-state cost. Preserve the MIT notice and source pin if code is incorporated. Treat upstream fpsTarget metadata as a target, not a measurement. The basic successful probe does not justify replacing the working default application with an unverified weather path.

## Cached integration checkpoint

The adapter uses a direction-preserving cube cache:256px faces at High refreshed every0.25simulation seconds;128px faces at Low refreshed every0.75seconds. Both use Eanpa24/8/1 sampling and sky-local tone mapping. One target resizes only on quality changes and is disposed with the owner. The old lightweight parallel sky was removed. Native atmosphere checks verify visual contribution, fish visibility and geometry stability across quality changes. HardwareWebGL2 river captures had no captured shadererrors. Full software entry/optics and matched performance remain pending; cloud softness/grain is not accepted finalart. No performance speedup claim follows from capture success.
